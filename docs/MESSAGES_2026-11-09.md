## Changes

| # | Problem | Fix |
|---|---|---|
| 1 | After the designer closed a conversation, the customer could never write about that project again. | Writing in a closed conversation reopens it. The customer sees "This conversation was closed by the designer. Sending a message will reopen it." and the designer sees "You closed this conversation. Sending a message will reopen it." Contact Designer on the same project opens that conversation with a message box. |
| 2 | A message sent from an old first-message form (a second tab, or an old drawer) was dropped, with "You already have a conversation for this project." | The message is added to the existing conversation and "Message sent." is shown. An identical repeat (a double click or a retry) is still saved only once. If the conversation is unavailable, for example because the designer is suspended, it says "Messages are unavailable for this conversation." |
| 3 | The floating Messages button covered page content on phones, e.g. "See All" on the customer home page. | On phones (560px wide or less) there is no floating button. Customers get a Messages icon in the top bar, next to their avatar. Designers use the Messages menu link. The drawer opens as a bottom sheet. On computers the floating button stays. |
| 9 | Customers saw the designer's words: "New" right after sending. | Customers see **Waiting for Reply** and **Designer Replied**. Designers keep **New** and **Replied**. Both see **Closed**. |
| 11 | There was no sign of new messages. | A number shows how many conversations have unread messages. It appears on the floating Messages button, the customer's phone icon and the designer's Messages menu link. Each conversation in the list shows "1 unread message" or "2 unread messages". Opening a conversation marks it read and the number updates without reloading the page. Your own messages never count. |
| Extra | In the drawer, Confirm Close sent the form to `/designer/[object HTMLInputElement]` (404) and showed "Could not confirm the message." (`drawer-close-bug-before.log`). The Close form has a field named `action`, which hides the form's `action` address in JavaScript. | The drawer script reads the address with `getAttribute("action")`. |

## Code changes (B-C-E)

| Layer | Change |
|---|---|
| Boundary | `ConsultationPanel` passes each role's status words (`STATUS_LABELS`) and sends the unread count to the drawer in the `X-Consultation-Unread` header. `render()` in `ui.py` adds `unread_messages` to every page through `unread_message_count()`. `base.html` adds the badges and the phone top-bar icon. `_panel.html` shows the status words, unread counts and the reopen notes. `consultations.js` updates the badges (`updateBadges`) and fixes the Close form address. |
| Control | New `CountUnreadMessagesController` (`execute` / `validateRequest`, like the other controllers). |
| Entity | `Consultations.start()` adds the message to an existing conversation (`_isRepeat` skips an identical retry). `reply()` and `start()` share `_continue()`, which reopens closed conversations. `viewThread()` marks messages read. New `countUnread()`; `listFor()` returns an `unread` count per conversation. |
| Database | `consultations` gains `customer_last_read_id` and `designer_last_read_id` (the newest message each side has opened). `migrate()` adds them to an older database. |
